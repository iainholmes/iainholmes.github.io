Canonical repository: `iainholmes/iainholmes.github.io`; branch: `master`. The GitHub Pages paths are permanent. A task completion message, a local draft, a Library backup or an API request being sent is not proof of publication.

Normally select at most two stories per major domain and at least three different domains. Keep exactly five stories. Document material-development overrides with prior/new status, reason and a primary evidence URL; document deliberate diversity exceptions. Do not rewrite old news to simulate novelty.
4. Prepare original dated artwork before publication. `node scripts/prepare_periodicals.cjs` appends immutable entries to `personal-updates/issue-mark-archive.js`, appends missing L&L `#field-studies` entries, and refreshes hub cover/metadata fallbacks. It leaves existing artwork authoritative even after incidental text edits. New cover subjects come from specific content; a repeated subject uses a different dominant composition. Preserve the pinned legacy plates and the corrected No. 008; never regenerate published plates. Run `node scripts/test_field_brief_artwork.cjs` to check append-only preparation, composition diversity and historical stability. L&L Field Studies primarily read `.synthesis`, use one conceptual scene, and continue sequentially. Original Field Study 001 is preserved. When publishing via connector without a local CLI, read these helpers and perform the same append-only artifact preparation; fetch and preserve the entire current archive. Include the new mark and updated hub in the coherent publication commit. Do not merely copy the previous artifact or bump its caption. Bump the hub's archive script query version when a new entry is appended so returning readers cannot keep stale artwork from browser cache.
5. Check JSON/markup, correct answer indexes and worked calculations, five-story contracts, chronology, archive preservation, and artwork. Run `node scripts/test_issue_marks.cjs`, `node scripts/test_periodicals.cjs`, and `node scripts/test_publishing.cjs` where a local execution environment is available. 6. Commit only intended publication/artwork/metadata files on a review branch. Inspect the complete diff; `/rupert/` and unrelated personal-site pages must be untouched. Before publishing, read `master` again. If another writer advanced it, fetch that state and rebuild the smallest isolated change against the new base; never force-push or overwrite a collaborator. Fast-forward only after checks pass.
7. Refetch the remote commit/file and verify that the new dated issue is newest, the number/content match, and earlier issues remain present. Then verify the public GitHub Pages URL after deployment, including the hub's latest metadata and mark. If deployment or content verification fails, report failure and retain the draft. Do not pretend the issue is live.
8. Only after successful repository publication and live verification, advance any publisher checkpoint or persistent backup. A failed write must not advance issue numbers, last-published state or backup markers. Keep an unpublished draft separately if needed for retry; it is not the canonical archive.

## Helpers and artifact schemas

`editorial-memory.js` is a publisher aid, not a client-side news feed. `history(editions, before)` excludes the candidate date, sorts newest first and takes at most seven. `assess(candidate, editions, before)` returns matching dimensions, raw penalty and a supported material-development override. Penalties count each dimension once per prior edition, with recency weighting. `review(stories, exception)` identifies diversity departures for editorial judgment. Explicit `story.editorial.domain` and arrays for the seven dimensions prevent ambiguous keyword-based classification from becoming a hard quota.

`issue-mark-archive.js` maps `publicationKey:YYYY-MM-DD` to the immutable model and SVG. `version:2` preserves the existing Workbook/L&L models; new Field Brief marks use `version:3`, with `subject`, `composition` and a structural `signature`; `frozen` is the authoritative illustration. Legacy entries retain their exact original SVG. `issue-marks.js` reads the registry before generating anything and exposes `model`, `svg` and `update`. For an unregistered new mark, pass the immediately preceding model as `previous`; preparation does this chronologically for every publication.

New Workbook marks use `version:4`: question stems and concepts support a named structural composition, with broad course vocabulary weighted below specific concepts. Exclude the preceding three effective compositions. Legacy section/rotated-plan variants count as the same structure. Preparation checks this before pinning; the hub reconstructs missing recent context from canonical sets when returning from a cached session. Run `node scripts/test_workbook_marks.cjs` and the WebKit shelf regression `scripts/test_shelf_browser.cjs` for artwork, fallback/refresh parity and return-state geometry.

## Loblolly & Logit cumulative notebook review

Every Friday edition includes an editorial review of all five readings and the synthesis against `weekly-economics-environment/notebook/index.html`. This is part of publication, including recovery of an edition whose content already exists. The notebook is cumulative: never regenerate it or replace earlier entries. Preserve canonical explanations, permanent concept anchors, sequential numbers and every earlier reference. Append references only when a later reading substantively revisits the concept; update `Last revisited` to the newest genuinely relevant edition date. Add an entry only for a distinct reusable idea warranted by the published research, with a canonical explanation, economic relevance, methodological caution and journal links. There is no minimum number of additions.

Append the issue date to `weekly-economics-environment/notebook/reviews.json` (version 1). Each review has `reviewedOn` (the actual review date), `readings` (all five permanent article IDs), `synthesis` (its section ID), `revisited` and `added` (concept-anchor arrays), and `note` (the editorial decision, including why no additions are warranted when applicable). An audit completed later records its real review date rather than backdating it. A valid no-addition review may have empty action arrays and a substantive note; never fabricate content to satisfy a check.

Run `node weekly-economics-environment/notebook/validate.cjs`, then `node scripts/prepare_periodicals.cjs`, then `node scripts/test_notebook.cjs` before committing. Preparation runs the read-only notebook validator **before writing any artwork or fallback artifacts**. Missing reviews—including for the newest canonical edition—fail actionably. The validator checks five-reading/synthesis coverage, permanent reference targets, unique concept/index/reference IDs, and revision dates supported by those references. It cannot establish academic relevance: the publisher must read the research and make that judgment. A retry merges into the same dated review and appends only missing references/concepts; it must not duplicate entries, change revision dates without new evidence, or rewrite previous review decisions.

Check notebook → article/edition and journal → notebook links on desktop and iPhone. Commit the journal, cumulative notebook and dated review together with the required publication artifacts. Refetch current master before integrating; preserve concurrent work. Verify the public notebook and review registry after GitHub Pages deployment. The Friday publisher and Periodicals Publish Check must both require the review; an existing edition section alone is not proof of completed L&L publication.

## Workbook learning content and local records

Every Workbook question requires authored HTML fields `assistance` and `explanation`. Keep the existing question, options, answer key, references and permanent ID intact. Assistance teaches the method without naming the correct option or performing the actual question's calculation; worked examples use different inputs. Explanation can complete the actual calculation and discuss the answer choices. These fields belong to the published dated question and remain stable thereafter. Never fetch a runtime tutor response or silently replace historical learning content.

Run `node daily-econ-challenge/learning-schema.cjs` to validate all current questions, or pass a candidate JSON/HTML file. Preparation runs the same validation before writing artifacts. Safe prose, mathematical HTML, short code/output excerpts and small semantic tables are supported; active content, hidden content, unsupported HTML and duplicate generic Assistance are rejected. Automated validation cannot substitute for editorial review of whether Assistance gives away the answer. Run `node scripts/test_workbook_learning.cjs` and the relevant browser regressions before release.

Reader answers retain the `dec:v1:<date>` storage contract. A record may additionally contain `committed` (the submitted selection for each question), `learning` (question-level `assistanceUsed`, `assistanceOpen`, `explanationOpen`) and `viewedAt`. The shared Workbook reading record names the last viewed set and question, whether answered or not; completion does not remove that location. Older answer records remain readable. Changing a selection makes that question a draft again; final set submission commits the whole set. Assistance use counts distinct questions within an attempt and never changes the score.

The return panel offers Resume only. Start Fresh is confirmed in the Ledger and clears this browser's Workbook answer/learning/completion records, Workbook reading location and Workbook seen-set record, then opens the first published set at Q1. Per-set Retake is also confirmed in the Ledger and leaves other sets intact. Neither action deletes published content or Commonplace keeps. Cancelling confirmation writes no record.
