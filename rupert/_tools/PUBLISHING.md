# Guarded Atlas release

Optional personal experience history is supplied privately via `--history PRIVATE_HISTORY.json` or the deliberately installed ignored `rupert/_private/recommendation-history.json`. The canonical release guard applies completion-sensitive reuse before promoting a draft, in addition to all access/weather/editorial gates below. Historical publications are not retroactively re-evaluated using new personal data. Rank the authored candidate queue with the existing `recommend.mjs` before preparation. Never commit the private export; see [EXPERIENCE-HISTORY.md](EXPERIENCE-HISTORY.md).

Canonical sources are the edition JSON files, public place records, artwork registry and official access checks under `/rupert/`. `data/editions/index.json` is generated, never edited to release a recommendation. Prepared editions stay `draft` until reviewed and actually released.

**Native artwork is part of publication:** Monday/Wednesday preparation supplies verified recommendations through the existing owner-only Drive packet; an artwork reserve is optional, never a prerequisite. Use `private-staging.mjs seal/check --recommendations` for that recommendation-only handoff. At the due Tuesday/Thursday run, select and verify the recommendation, generate one original illustration with the native ChatGPT image tool, obtain its real file, inspect it and import its derivatives using the existing tools. Complete the local packet with that single fresh illustration, then use the unchanged guarded stage/publish path. See [PRIVATE-PREPARATION.md](PRIVATE-PREPARATION.md). Keep unpublished data/images in ignored working storage and off every public branch/URL. Historical artwork pins and all release safeguards remain mandatory. No paid API, API key, new service or artwork automation is required.

Tuesday and Thursday are due at 07:00 America/New_York. The slot is attached to the current Saturday–Sunday edition week. A delayed draft remains pending everywhere, including the veil. The release command records actual wall-clock time with the correct Eastern offset; it has no production clock override.

1. Fetch latest master into a clean branch. Validate prepared canonical content with `node rupert/_tools/rupert.mjs check`. If no draft is prepared, report the missing due slot and perform authentic research and private preparation as below; never fabricate a recommendation or treat absence as successful publication.
2. Review the land manager's current official home/status, alerts/news, trail listing, access hours/address, route and dog policy. Append evidence to `data/access-checks.json` with the public `place_id`, today's Eastern `checked` date, actual ISO `checked_at`, approved `official_url`, truthful `status`, `discrepancy` and factual `note`. Never interpret an inaccessible source or absent third-party alert as proof of open access. Retain older dated checks for historical editions.
3. Artwork belongs to this publishing execution: use the existing illustration specifications and approved references, generate one previously unpublished native illustration after selecting a viable recommendation, inspect the native result, and obtain its actual image bytes. Import through `prep_photos.py` in ignored working storage, retain the actual generation date, record ownership/brief/characters and genuine visual review, and complete the local packet before `stage`. Do not preassign a plate number; the canonical guarded release assigns the next number and freezes its association. A still-unpublished image from this same slot’s failed attempt may be retained for its retry/independent fallback, never recycled from another published plate. Native generation may inherently display in the run conversation: do not claim it stayed unseen, deliberately attach extra previews, describe it in notifications, or block solely because that native display cannot be suppressed.
4. Run `node rupert/_tools/publish.mjs refresh EDITION_ID`. On Node 24 in a proxy environment use `node --use-env-proxy`; normal network environments do not need that flag. The command fetches NWS `/points`, the returned forecast and active alerts for the **public trailhead**, not Home. It requires Saturday and Sunday daytime periods and a source issue less than three days old. Provider text is preserved; evening periods and alerts are available for the safety review. The original snapshot/source is archived in `data/conditions-history.json`. Failure produces an explicit unavailable state, with no forecast rows or fair-weather claim.
5. Read the actual returned forecast/alerts and check the editorial advice against it. Update the condition headline, level, summary, trail note, best window and pivot when necessary. Never suggest another exposed outdoor trail as a thunderstorm alternative or invent a closure check. An unavailable source does not establish benign weather; withhold unsafe advice. Keep historical source timestamps and original recommendation data.
6. Review access, dog policy, trail details, artwork and safety after the refresh. Append `data/editorial-reviews.json` → `reviews`: `edition_id`, actual `reviewed_at`, the exact `conditions_as_of`, `ready` boolean and a substantive `note`. Approval is specific to the refreshed evidence, not reusable on a subsequent issue/date. Update the public place snapshot date only when its details were genuinely reviewed. A closed, disputed, stale, premature or unreviewed recommendation cannot pass the release gate.
7. `node rupert/_tools/publish.mjs release` checks all due drafts without changing status. `release --apply` validates again, promotes ready drafts at the actual instant, records nominal and actual times in `data/release-log.json`, and builds all pages. It is idempotent after publication. If any due draft is blocked, stop and report the concrete blocker; do not force status or weaken validation.
8. Run `npm test --prefix rupert`, build/check, `node rupert/_tools/rupert.mjs audit --history` and focused browser checks. Preserve draft exclusion, withdrawn history, current-week slots, source provenance and Home privacy. Re-fetch master, reconcile unrelated remote changes, confirm the diff is `/rupert/` only, fast-forward without force push, wait for GitHub Pages success, and compare public assets to committed bytes. Report an actual blocker/failure; a local build is not production verification.

The connected scheduled publisher performs this procedure, with hourly retry opportunities after the nominal release. It is an editorial automation, not a GitHub Actions workflow. Timing is a wake-up, not a publication signal. An early wake-up must recheck the actual clock at or after 07:00 before claiming that slot has run. A due slot with neither a draft nor a released edition makes `release` exit nonzero with preparation instructions, even if another slot has a draft. Previously released withdrawal notices remain history under the existing publication contract. The site remains pending until actual validated publication.

## Preparation before the release window

Research, public trailhead verification and route/dog/access checks should finish on Monday/Wednesday before the corresponding Tuesday/Thursday window. Seal two authentic independent candidate drafts with `artworks:[]` using `--recommendations`, and update the same owner-only operational packet after permission checks and exact readback. Do not generate artwork in the preparation task. Keep research, personal history and unpublished drafts private. Preparation is not approval of publication-day evidence.

At release time the existing Work publisher fetches current master, validates the recommendation handoff, chooses a viable destination, generates and inspects one original native illustration, and completes the local packet for the existing isolated stage/release procedure. Missing preparation requires genuine research, not an automatic no-op. Each destination still gets its own fresh official-access/NWS/safety/editorial review. Generate close to publication; do not build or require an artwork stockpile. The existing optional reserve/staging implementation is retained and compatible. Keep the Monday/Wednesday approximately 15:00 preparation and Tuesday/Thursday 07:00/08:00/09:00 publishing schedules; do not create another automation.

Every due failed attempt must report the slot, exact blocker, completed reusable artifacts, next safe action and whether the retry remains available. After the last retry, explicitly report that the edition is still missing. Do not suppress missing/blocked publication with a silent completion marker. A successful report requires the master commit, successful Pages deployment and a verified live edition; a local release or draft alone is insufficient.

## Corrections and browser freshness

Refreshing an already-published current-week edition does not change its publication timestamp. Rebuild/deploy the correction and retain the previous forecast in history. The manifest's content revision invalidates same-ID weather snapshots. This Week, Archive and Atlas recheck every minute, on visibility resume and `pageshow`; Full Edition conditions do likewise. Offline pages keep clearly dated snapshots rather than manufacture new information.

Full Edition Drive facts use local `rupert-location-v1` Home coordinates with the existing OSRM router. A result is reused for five minutes in memory; Home changes, reload and resume trigger the appropriate recheck. On missing/invalid Home, timeout or routing failure, the labeled Chapel Hill reference estimate remains. The address is neither read nor sent; Home coordinates go only to OSRM as already disclosed in Atlas. Never write those coordinates into public data, logs or reports.
