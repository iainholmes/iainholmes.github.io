# Guarded Atlas release

Canonical sources are the edition JSON files, public place records, artwork registry and official access checks under `/rupert/`. `data/editions/index.json` is generated, never edited to release a recommendation. Prepared editions stay `draft` until reviewed and actually released.

Tuesday and Thursday are due at 07:00 America/New_York. The slot is attached to the current Saturday–Sunday edition week. A delayed draft remains pending everywhere, including the veil. The release command records actual wall-clock time with the correct Eastern offset; it has no production clock override.

1. Fetch latest master into a clean branch. Validate prepared canonical content with `node rupert/_tools/rupert.mjs check`. Do not fabricate a recommendation if none is prepared.
2. Review the land manager's current official home/status, alerts/news, trail listing, access hours/address, route and dog policy. Append evidence to `data/access-checks.json` with the public `place_id`, today's Eastern `checked` date, actual ISO `checked_at`, approved `official_url`, truthful `status`, `discrepancy` and factual `note`. Never interpret an inaccessible source or absent third-party alert as proof of open access. Retain older dated checks for historical editions.
3. Run `node rupert/_tools/publish.mjs refresh EDITION_ID`. On Node 24 in a proxy environment use `node --use-env-proxy`; normal network environments do not need that flag. The command fetches NWS `/points`, the returned forecast and active alerts for the **public trailhead**, not Home. It requires Saturday and Sunday daytime periods and a source issue less than three days old. Provider text is preserved; evening periods and alerts are available for the safety review. The original snapshot/source is archived in `data/conditions-history.json`. Failure produces an explicit unavailable state, with no forecast rows or fair-weather claim.
4. Read the actual returned forecast/alerts and check the editorial advice against it. Update the condition headline, level, summary, trail note, best window and pivot when necessary. Never suggest another exposed outdoor trail as a thunderstorm alternative or invent a closure check. An unavailable source does not establish benign weather; withhold unsafe advice. Keep historical source timestamps and original recommendation data.
5. Review access, dog policy, trail details, artwork and safety after the refresh. Append `data/editorial-reviews.json` → `reviews`: `edition_id`, actual `reviewed_at`, the exact `conditions_as_of`, `ready` boolean and a substantive `note`. Approval is specific to the refreshed evidence, not reusable on a subsequent issue/date. Update the public place snapshot date only when its details were genuinely reviewed. A closed, disputed, stale, premature or unreviewed recommendation cannot pass the release gate.
6. `node rupert/_tools/publish.mjs release` checks all due drafts without changing status. `release --apply` validates again, promotes ready drafts at the actual instant, records nominal and actual times in `data/release-log.json`, and builds all pages. It is idempotent after publication. If any due draft is blocked, stop and report the concrete blocker; do not force status or weaken validation.
7. Run `npm test --prefix rupert`, build/check, `node rupert/_tools/rupert.mjs audit --history` and focused browser checks. Preserve draft exclusion, withdrawn history, current-week slots, source provenance and Home privacy. Re-fetch master, reconcile unrelated remote changes, confirm the diff is `/rupert/` only, fast-forward without force push, wait for GitHub Pages success, and compare public assets to committed bytes. Report an actual blocker/failure; a local build is not production verification.

The connected scheduled publisher performs this procedure for prepared recommendations, with hourly retry opportunities after the nominal release. It is an editorial automation, not a GitHub Actions workflow: the `/rupert/`-only boundary prevents adding repository-root workflow infrastructure in this pass. Timing is a wake-up, not a publication signal. The site remains pending until actual validated publication. No edition is automatically invented for a future weekend.

## Corrections and browser freshness

Refreshing an already-published current-week edition does not change its publication timestamp. Rebuild/deploy the correction and retain the previous forecast in history. The manifest's content revision invalidates same-ID weather snapshots. This Week, Archive and Atlas recheck every minute, on visibility resume and `pageshow`; Full Edition conditions do likewise. Offline pages keep clearly dated snapshots rather than manufacture new information.

Full Edition Drive facts use local `rupert-location-v1` Home coordinates with the existing OSRM router. A result is reused for five minutes in memory; Home changes, reload and resume trigger the appropriate recheck. On missing/invalid Home, timeout or routing failure, the labeled Chapel Hill reference estimate remains. The address is neither read nor sent; Home coordinates go only to OSRM as already disclosed in Atlas. Never write those coordinates into public data, logs or reports.
